# Адресный индекс сценариев, 2026-09-13

## Источник и процедура

На опубликованном `sprut-agent` 0.1.14, commit
`656e81b821740c20a864ef1665b0ff124f5aa922`, Architect вызвал поставляемый
публичный MCP `get_entity` для характеристики `On` одной обезличенной офисной
лампы с `include=["relations"]`. Использовались bundled runtime и стандартный
MCP SDK, без браузера и скрытых RPC. Вызов был только на чтение, после него клиент
закрыт.

Первая попытка была отклонена локальной схемой: запрошенный `max_bytes=48000`
превышал опубликованный максимум 32768. После исправления аргумента один валидный
вызов завершился успешно. Это ошибка вызова, а не наблюдение отказа SprutHub.
Секреты, исходные имена и raw trace в этот материал не перенесены.

## Наблюдение (R)

Ответ от `2026-09-13T10:41:27.796Z` содержал:

- `scenario_accessory_index=found`;
- известный `BLOCK` с индексом-псевдонимом `31` в
  `scenario_associations`;
- три `scenario_roles`, раскрытые из конфигурации этого BLOCK;
- десять остальных BLOCK каталога и девять LOGIC/GLOBAL как непрочитанные
  области прежнего контракта;
- `extensions=not_read` и `runtime_execution=not_observed`.

Таким образом, native запрос `scenario.list` с `aId` способен вернуть известную
связь выбранного аксессуара, а последующее адресное чтение BLOCK способно
установить роли. Пустой индекс, ранее наблюдённый для другого устройства, сам по
себе не доказывает поломку этого механизма.

## Границы доказательства

Один положительный ответ не устанавливает полноту native accessory index для
всех BLOCK, LOGIC, GLOBAL, code-узлов, динамически выбранных целей, extensions
или фактического runtime. Ассоциация не доказывает направление влияния; роль
подтверждает только прочитанная конфигурация конкретного BLOCK. Наблюдение не
проверяло пустой индекс, ошибки источника, физическое исполнение и отсутствие
других влияний в доме.

Поэтому адресный `relations` использует индекс как ограниченную выборку и не
сравнивает её автоматически с полным каталогом. Широкий `inspect_home` и явное
чтение выбранной конфигурации остаются отдельными инструментами для вопроса,
которому действительно нужен более широкий поиск.

## Влияние на состояние дома

Изменений в конфигурации и физических командах не было.
