## S001 — Первичное исследование web-клиента

- Цель: определить транспорт и наличие формального API-контракта.
- Источник: авторизованная web-панель `https://beta.spruthub.ru/` и публичные
  hashed assets текущей страницы.
- Версия web-клиента: `1.5.58`.
- Build: `2025-09-16T14:32:15.361Z`.
- Влияние на дом: отсутствует; команды устройствам и настройки не отправлялись.

### Процедура

1. Прочитана доступная DOM-структура загруженной панели.
2. Получен список загруженных JavaScript assets.
3. Публичные bundles скачаны во временный каталог.
4. Выполнен статический поиск транспорта, envelope и встроенных схем.

### Наблюдения

- Клиент создаёт WebSocket на `wss://beta.spruthub.ru/spruthub`.
- Поддерживаемые subprotocol: `json-rpc` и опциональный `protobuf`.
- Request context содержит `id`, `cid`, token и serial активного хаба.
- JSON-операция кодируется вложенной структурой
  `params.<domain>.<operation>`.
- Ответ коррелируется по `id`.
- Сервер поддерживает асинхронные события без request `id`.
- Timeout запроса в web-клиенте — 10 секунд.
- В bundle обнаружены исходные protobuf-схемы.

### Подтверждённый вывод

Основной API web-панели — stateful WebSocket RPC, а не REST. Protobuf-схемы
могут служить первичным формальным контрактом.

### Ограничения

- Реальные WebSocket frames ещё не записывались.
- JSON envelope подтверждён client code, но пока не имеет статуса `O`.
- Token lifecycle и права доступа не исследованы.

### Артефакты

- `docs/api-reverse-engineering.md`

## S005 — Read-only WebSocket recorder

- Цель: получить статус `O` без чтения browser storage и без MITM TLS.
- Артефакт: `research/record-websocket.mjs`.
- Влияние на дом: отсутствует; recorder только слушает CDP Network events.

### Ограничения recorder

- Подключается к отдельной Chromium/Chrome сессии с включённым CDP.
- Не читает cookies, localStorage, sessionStorage или password fields.
- Не записывает request/response handshake headers.
- Из handshake сохраняется только negotiated WebSocket subprotocol.
- Фильтрует только socket с origin Sprut.hub и path `/spruthub`.
- Raw NDJSON создаётся с правами `0600` в gitignored-каталоге.
- Recorder не кликает UI и не отправляет WebSocket frames.

### Проверка

- Выбор CDP target протестирован.
- Фильтрация посторонних sockets протестирована.
- Направление, opcode и payload frame сохраняются без преобразования.
- Общий test suite: 9 тестов, все прошли.

### Следующий шаг

Нужна отдельная debuggable browser session. После ручной авторизации recorder
должен быть запущен до reload страницы, чтобы увидеть создание socket и
baseline frames.

## S006 — Account authentication state machine

- Источники: `Account.proto`, auth store и login component web-клиента.
- Влияние на дом: отсутствует; существующий token не читался.

### Восстановленный контракт

1. Клиент генерирует `cid`.
2. `account.auth` отправляет map входных route params.
3. Сервер отвечает `AccountResponseMessage`.
4. Если есть `question`, клиент отправляет `account.answer { data }`.
5. Цикл продолжается до token либо terminal status.

Question types:

- email;
- password;
- new password;
- captcha;
- PIN email;
- PIN SMS;
- add hub;
- unsupported device.

Response statuses:

- success;
- failed;
- not confirmed;
- invalid format;
- not connected;
- no more tries;
- too fast.

Response также может содержать form label: header, text, error и button.

### Неизвестные свойства

- token TTL и refresh/renewal semantics;
- отзыв token;
- scope account/admin;
- зависимость token от `cid`;
- поведение параллельных клиентов;
- поведение после смены пароля;
- точные wire fixtures каждого question type.

## P001 — Политика read/write

- Read-only исследования разрешены пользователем.
- Любая операция, меняющая дом, устройство, характеристику, сценарий,
  контроллер, мост, настройки или account, требует отдельного явного одобрения.
- До одобрения запрещены `characteristic.update`, `scenario.run`, create,
  delete, setOptions, restart, upgrade, reset, discovery/exclusion и другие
  команды с возможным внешним эффектом.
- Открытие разделов и карточек в UI допустимо только когда оно не подтверждает
  и не отправляет изменение.

## S007 — Structural diff snapshots

- Цель: локализовать изменения протокола между двумя версиями web-клиента.
- Источник: два локальных обезличенных snapshot.
- Влияние на дом: отсутствует; сеть и WebSocket не использовались.

### Реализация

`research/compare-snapshots.mjs` сравнивает:

- операции и request/response contracts;
- messages и поля, включая numbers, types, labels и oneof;
- enums и числовые значения;
- hashes отдельных `.proto`;
- hashes scenario JSON schemas;
- hashes client assets по логической роли.

Результат имеет категории `breaking`, `review`, `additive` и
`behavioralUnknown`, а также общий verdict `unchanged`,
`compatible-additive`, `review` или `blocked`.

### Проверка

- Добавлено 6 unit tests diff.
- Добавлен тест immutable snapshot selection для hotfix build с тем же номером
  версии.
- Общий suite: 16 tests, все прошли.
- Self-diff snapshot `1.5.58 -> 1.5.58`: `unchanged`, 0 изменений.
- Повторное извлечение неизменившегося build вернуло `reused: true` и не
  перезаписало snapshot.

### Ограничения

- JSON Schema пока сравнивается по hash; semantic tightening/relaxing
  классифицируется как review.
- Изменение JS bundle сообщает о поведенческой неопределённости, но не
  локализует её без observed fixtures.

### Артефакты

- `research/compare-snapshots.mjs`
- `research/compare-snapshots.test.mjs`
- `docs/protocol-evolution.md`

## P002 — Quarantine новых версий

- Новая комбинация web client build и hub firmware не становится active
  автоматически.
- Сначала создаётся immutable snapshot со статусом `quarantine`.
- Breaking diff блокирует promotion.
- Additive diff позволяет сгенерировать новый wire codec/catalog, но не
  включает новые write capabilities.
- Любое изменение client code требует read-only smoke, даже если proto и
  scenario schemas не изменились.
- Проверка write после обновления выполняется только при необходимости и
  требует отдельного явного одобрения пользователя.
- Последний known-good profile сохраняется для клиентского rollback.
