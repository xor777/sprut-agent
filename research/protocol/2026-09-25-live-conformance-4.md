# Живое соответствие, прогон 4: новые узлы BLOCK

2026-09-24, 21:44 UTC (2026-09-25 00:44 по времени хаба). Задача: проверить,
как хаб хранит узлы BLOCK, добавленные в `e170087`: «каждые N», повтор ветки,
значение из другой характеристики, уведомление, HTTP-запрос и режимы
управления другим сценарием.

## Источник и полномочия

- Хаб: firmware 3.0.0, revision 20131, model 2.
- sprut-agent 0.2.0 плюс локальные изменения, `research/live-conformance.mjs
  --only 1,V,2` на `e170087`, собранный `dist/plugin/dist/server.mjs` того же
  коммита. Префикс прогона `20260924T214433Z`.
- Каждый BLOCK создан выключенным, с триггером на дату в 2030 году, и
  действует только на виртуальный аксессуар прогона. Уведомления и запросы
  не отправлялись: сценарии не включались и не запускались. HTTP-узел
  указывал на `http://127.0.0.1:9/`.
- Итоговый снимок дома совпал с начальным; объектов прогона не осталось.

## Наблюдения

| Форма | Отправлено | Хранится |
| --- | --- | --- |
| «Каждые N» (`0/15` в поле минут, `mode: NONE`) | как в веб-клиенте | как отправлено |
| Повтор ветки (`then_delay`, `else_delay` 60000) | как в веб-клиенте | как отправлено |
| HTTP (`{type: http, method: GET, url}`) | как в веб-клиенте | как отправлено |
| Режимы сценария (ACTIVATE, DEACTIVATE, ACTIVATE_AND_FIRE, RESET) | как в веб-клиенте | как отправлено |
| Значение из характеристики (`type: from`) | с `value: ""` | без `value` |
| Уведомление MESSAGE | без `to` | как отправлено |
| Уведомление PUSH всем | `to: null` | без `to` |
| Уведомление PUSH одному сервису | `to: [{index: "telegram_1", clients: null}]` | `to: [{index: "telegram_1"}]` |

Хаб отбрасывает `null` и пустую строку в этих полях; пустые списки `then: []` и `else: []` он хранит (прогон 3).
Продукт на `e170087` сравнивал дословно, поэтому свои BLOCK с `from` и
уведомлением принял за изменённые и отменой не удалил; их удалила уборка
прогона.

Сервисы уведомлений хаба (чтение `home_overview list=extensions` и
`get_entity include=children`): `Notification:telegram_1` включён, состояние
FAILED, 0 получателей; `Notification:web_1` LOADED, 1 получатель.

## Повтор после исправления

На `4ef5609` (каноническая форма считает `null` отсутствующим полем, а `from`
с `value: ""` — узлом без значения; продукт больше не добавляет эти поля)
тот же прогон (префикс `20260924T223452Z`): все формы, включая `from` и
уведомления, прочитаны как совпадающие, все BLOCK прогона удалены отменой
продукта, уборке ничего не осталось, итоговый снимок совпал с начальным.

## Границы

- Хранение проверено; исполнение этих узлов (отправка уведомления, запрос,
  повтор, чтение значения) не проверялось.
- Один хаб, одна прошивка, без повторов.
