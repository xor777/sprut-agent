## Подтверждённый контракт

Account-level `hub.list` вызывается без поля `serial` и возвращает доступные
хабы, включая их native serial. Последующие RPC относятся к одному выбранному
serial. Ссылки внешнего инструмента кодируют serial как URI-компонент и не
содержат token или cid.

`accessory.get(id)` возвращает дерево service/characteristic и поля
`extensionKey`, `deviceId`, `deviceWindow`. Наблюдённый
`window.get({ windowKey: deviceWindow })` возвращает окно с options. У
контрольного датчика option `SensorDetectionSeconds` имел настроенное значение
10. Его native key оканчивался на 60, но это часть адреса option, а не
самостоятельный report. Отдельный Info-фрагмент сообщал значение 60, но общего
полного native ID между ним и option не доказано: совпадение имени свойства
небезопасно при нескольких endpoints. Поэтому адаптер не связывает HTML report с
option; structured `reported_value` остаётся неизвестным, а безопасный Info-текст
доступен как отдельная диагностика. Явного признака ожидания применения и времени
источника ответ не дал.

Идентичность extension instance задаёт `extensionKey`, а не общий `type`:
например, два bridge одного типа должны иметь разные ссылки. Если непустого
уникального `extensionKey` нет, стабильная ссылка не создаётся. Строковый `owner`
из `hub.list` — native identity, но без текущей user identity он не доказывает
наличие или отсутствие ownership прав.

Window options включают не только конфигурацию: GROUP задаёт layout, BUTTON —
команду, а NUMBER с min/max/step — редактируемую настройку. Эти классы
возвращаются раздельно; значение команды не объявляется текущей конфигурацией.

Тип и содержимое сценария устанавливаются по полям ответа, а не по имени:
BLOCK data разбирается как JSON, GLOBAL/LOGIC может быть кодом. Диагностический
текст устройства и код сценария являются данными хаба, раскрываются только по
явному запросу. Распознанный credential container, PASSWORD control/option или
sensitive native объект скрывается целиком вместе с identifier и неизвестными
потомками; известный credential free-text blob заменяется целиком. Обычные
соседние данные сохраняются. Классификация выполняется до проекции native объекта
и до разбора object/array/scalar; redacted marker явно разрешён публичным типом
reading и остаётся терминальным при последующем `include` и финальной обработке.
Точное известное значение connection token защищается также в JSON-key: скрывается
ближайший содержащий его объект, а не весь ответ. Это не обещание распознать любой
произвольный секрет в свободном коде.

## Границы

На целевой учётной записи `hub.list` наблюдал один дом. Сквозной MCP-путь
`list_homes` → `inspect_home` → `get_entity`, сценарии, расширения и настройки
проверены на версии `5d1372d` 9 сентября 2026 года; сохранённая запись прежней
автоматизации осталась узнаваемой. Отдельный свежий агент выполнил пять успешных
read-вызовов и разобрал реальную BLOCK-конфигурацию. Источники и ограничения —
комментарии #1283–1284 в [SPRUT-18](https://plan.nuanu.ai/project/SPRUT/issue/18).
Это не живая проверка двух домов или физического повторного срабатывания датчика.
Архивный `device.getOptions` ответил `Module not found`, поэтому он не является
частью рабочего контракта.
