# Граница повторной команды и native event

O20260911-native-event-boundary, 2026-09-11. Цель — проверить, обязана ли
повторная подтверждённая команда с тем же значением порождать отдельное native
event и новый запуск BLOCK. Наблюдение выполнено через публичный MCP на
опубликованном кандидате `cf325688857e083029c02f7847dd2d57e641b520`.
Идентификаторы и имена дома удалены; полная трасса осталась приватной.

Временно создан BLOCK без команд устройствам: одна boolean-характеристика была
и `trigger`, и условием `true`; `if.mode` — `EVERY`, внутри выбранной ветки —
пустой delay `RESET` на 3 секунды. Во время одного native observation через
публичный write-path отправлены две отдельные команды `true` с интервалом около
1,6 секунды. Обе команды получили native ACK и были подтверждены отдельным
чтением. Первая сопровождалась characteristic event и событием исполнения
сценария до входа в delay. Для второй ни characteristic event, ни нового
исполнения сценария не наблюдалось. Последующая команда `false` дала новое
вычисление условия.

После опыта временный BLOCK удалён через restore с ACK и readback; независимый
каталог подтвердил его отсутствие. Значение характеристики возвращено к
прочитанному исходному состоянию. Датчики и соседние настройки не менялись.

Это устанавливает только границу проверенного command path: повторная принятая
команда с тем же значением не обязана порождать новый WebSocket event или запуск
проверки. Наблюдатель сохраняет повторы, которые хаб фактически отправил в
WebSocket, но не является журналом всех радиоотчётов. Опыт не отправлял и не
перехватывал радиопосылки датчика, поэтому не доказывает их наличие, отсутствие
или дедупликацию. Документированная семантика `EVERY` относится к выполнению
веток при уже запущенной проверке и не заполняет этот причинный разрыв.
