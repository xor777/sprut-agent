# Нативная настройка устройства: window.update

W20260910-window-setting, 2026-09-10 16:36 UTC. Цель — подтвердить изменение и
возврат одного параметра устройства для SPRUT-28. Идентификаторы ниже вымышлены.

## Источник и контракт (S)

Текущий [интерфейс SprutHub](https://beta.spruthub.ru/) загрузил
[app.16735171810a795a9f2d.js](https://beta.spruthub.ru/js/app.16735171810a795a9f2d.js),
SHA-256 `81c1ef74ce21eb5ccff583255ba82fe766ff4cf6bc251c0566b7bd67436647f8`.
Целевой хаб: 3.0.0 revision 20131. Номер сборки интерфейса не извлечён;
старый снимок 1.5.58 не является источником этого контракта.

Встроенная схема `WindowUpdateRequest` содержит `windowKey` и массив
`OptionUpdateMessage options`. У элемента есть `key` и типизированный `value`.
Ответ `WindowResponse.update` — `EmptyResponse`. `WindowScreen` использует
`window.get` для чтения и `window.update` для сохранения. Обработчик формы
передаёт массив из одного изменённого элемента, а не всё окно. Интерфейс
оптимистически обновляет локальный cache; это не доказательство записи на хабе.

Обезличенные `params` реально выполненной операции:

```json
{
  "window": {
    "update": {
      "windowKey": "Controller/zigbee_demo/Child/DEVICE_A/",
      "options": [
        {
          "key": "/11/0006_OnOff/4003_StartUpOnOff/255",
          "value": { "intValue": 0 }
        }
      ]
    }
  }
}
```

Адрес окна берётся из `accessory.get.deviceWindow`, ключ и тип значения — из
его `window.get.options`. Параметр имеет `type: GenericInteger`, `inputType: LIST`,
`read/write: true`, `disabled: false`. Его `validValues[].value.intValue`:
0 — всегда выключено, 1 — всегда включено, 2 — чередование, 255 — последнее
состояние. Текущее значение находится в `option.value`, не в `checked`:
у всех четырёх вариантов `checked: true`.

## Воспроизведение и возврат (R)

Полномочие пользователя: «с лампой я тебе разрешаю любые эксперименты.
с датчиками только чтение». Объект — ранее разрешённая лампа, не датчик.
Один отдельный клиент использовал существующую авторизацию. До записи
проверены принадлежность дому, связанный адрес окна, допустимый вариант и
неизменность исходного значения. Сохранены снимки до/после/возврата.

1. `window.get` прочитал `value: {intValue: 255}`.
2. Единственный элемент `window.update.options` установил 0. Получен
   `result: {window: {update: {}}}`. Новый RPC `window.get` прочитал 0.
3. После проверки текущего 0 тот же ключ возвращён в сохранённое 255.
   Новый `window.get` подтвердил 255.

В обоих сравнениях значения всех характеристик лампы, остальных параметров
окна и каталог сценариев совпали с исходными. Значения характеристик читались
из `characteristics[].control.value`; текущий свет оставался выключен,
яркость — 100. Команды характеристикам и сценариям не отправлялись. Записи
датчикам и другим устройствам не было. Клиенты завершены, изменённое значение
возвращено. Приватные исходники, probe и снимки сохранены локально; в Git и
Plan передаются только обезличенные наблюдения.

## Проверка поставляемого MCP

После независимого ревью SPRUT-28 кандидат
`01bafbf7bf89a87efdd09fa954655fe98d2ae691` прошёл тот же круг через публичные
`get_native_change_contract`, `prepare_native_change`, `apply_native_change` и
`get_native_change`. Отдельный read-клиент подтвердил 255 → 0 и неизменность
остальных параметров окна, характеристик лампы и каталога сценариев.

Первый MCP-процесс завершён. Второй процесс с тем же журналом нашёл change через
`list_native_changes` по ссылке окна и вернул сохранённое 255 через
`restore_native_change`. Независимое чтение подтвердило возврат и те же
инварианты. Манифест исходников, trace двух процессов и снимки сохранены
приватно. Это проверка настройки хаба, не физического включения после сбоя питания.

## Границы доказательства

- Подтверждено изменение читаемого значения хаба с узкой записью и возвратом.
  Отдельного reported/pending/ack устройства в этом параметре не получено.
  Физическое отключение питания, доставка до устройства и сохранение после
  его перезапуска не проверялись.
- Пустой ответ update не содержит итогового значения. После ответа или его
  потери нужен новый readback; cache интерфейса этого не заменяет.
- В схеме update нет версии, ожидаемого старого значения или CAS. Сверка
  перед записью обнаруживает наблюдённую чужую правку, но не обеспечивает
  атомарность с параллельным изменением между чтением и записью.
- Это наблюдение одной целевой настройки. Оно не доказывает одинаковую
  семантику кнопок, других controls и всех окон. Изменение настройки и
  компенсация физических эффектов — разные операции.
