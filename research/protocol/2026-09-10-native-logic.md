## Источник и контракт (S)

Исследованы `Logic.proto` и `LogicOptionsScreen` из официального
[app.16735171810a795a9f2d.js](https://beta.spruthub.ru/js/app.16735171810a795a9f2d.js).
SHA-256: `81c1ef74ce21eb5ccff583255ba82fe766ff4cf6bc251c0566b7bd67436647f8`.
Целевой хаб — 3.0.0 revision 20131. Старый снимок 1.5.58 не задаёт этот контракт.

Операции адресуются через `aId`, `sId` и, кроме каталогов, `type`.

| Операция | Наблюдённый смысл |
| --- | --- |
| `logic.types` | Доступные типы для выбранного сервиса; это не список назначений |
| `logic.list` | Фактически назначенные логики сервиса |
| `logic.create` | Создаёт назначение; в проверенном случае возвращает `active:false` |
| `logic.get` | Читает назначение, включая `active` и `optionsWindow` |
| `logic.getOptions` | Читает параметры именно этой логики |
| `logic.setOptions` | Принимает массив изменяемых `key` и типизированных `value` |
| `logic.update` | Изменяет `active` |
| `logic.delete` | Снимает назначение; не сбрасывает сохранённые параметры |

Пример `params` для одного числового параметра:

```json
{
  "logic": {
    "setOptions": {
      "aId": 11,
      "sId": 21,
      "type": "SmoothBrightnessChange",
      "options": [{ "key": "Duration", "value": { "intValue": 5 } }]
    }
  }
}
```

`setOptions`, `update` и `delete` отвечали пустым ACK внутри соответствующего
operation container. Итог проверялся отдельными `getOptions`, `get` и `list`.
ACK сам по себе не доказывает наблюдаемое состояние.

## Воспроизведение на хабе (R)

Полномочие владельца: «с лампой я тебе разрешаю любые эксперименты.
с датчиками только чтение». Все записи адресованы разрешённой лампе;
существующие сценарии и датчики не изменялись.

До назначения `SmoothBrightnessChange` её `get` и `getOptions` возвращали
`-32603 Not found`. Наличие доступного типа установлено через `types`,
отсутствие назначения — через список конкретного сервиса. Произвольная ошибка
чтения не доказывает отсутствия.

Первый `create` вернул неактивное назначение. Прочитаны `StartValue:1`,
`EndValue:100`, `Duration:900`; эти числа — исходное состояние данного хаба,
не доказанные заводские defaults. Все три параметра имели
`GenericInteger/NUMBER`, явные `read/write:true` и `disabled:false`.
`primary` — группа представления с `inputType:GROUP`, не дополнительная настройка.

Установка 1 → 40 за 5 секунд сначала меняла параметры неактивной логики,
затем её `active`. Отдельное чтение подтверждало каждый шаг. Настройка сама
не меняла `On` и `Brightness`; отдельный опыт с уже включённой лампой также
сохранил оба значения за шесть секунд наблюдения.

При последующем включении получены промежуточные значения яркости и итог 40.
В контролируемом опыте выключение во время перехода оставалось выключением
на протяжении последующих шести секунд. В более раннем опыте после выключения
произошло новое включение, источник которого не установлен. Это наблюдение
не исключено из результатов и не приписано автоматически сценарию движения.
Подписка на исполнения существующего сценария в следующем опыте не показала
его запусков. Логика не обещает приоритет ручного выключения над новой командой
другого сценария и не обещает сглаживание любого движения ползунка.

## Параметры переживают удаление (R)

После `delete` список назначений вернулся к исходному, но новый `create`
прочитал прежние 1/40/5. Следовательно, пустого списка недостаточно для
доказательства полного возврата: настройки сохраняются отдельно от назначения
по адресу сервиса и типа.

Исходные значения явно возвращены к 1/100/900 при неактивной логике,
прочитаны и назначение удалено. Ещё один независимый цикл create → getOptions
подтвердил 1/100/900, затем назначение снова удалено. Остальные назначения,
параметры физического окна и исходные значения характеристик сохранены.
Ранние отчёты о совпадении только списков назначений не являются доказательством
возврата этих скрытых параметров.

## Пустые параметры и границы

Назначенная `LightbulbControl` вернула
`{result:{logic:{getOptions:{}}}}`: известный пустой список параметров.
Это отличается от отсутствующего operation container, `null` и ошибки RPC.
Живое чтение через MCP на `d803ddd` сохранило сущность с `options:[]`.
Нельзя переносить такую трактовку на другие операции без их собственного
наблюдения; например, контракт `characteristic.getOptions` проверяется отдельно.

Сырые трассы, снимки, проверочные программы и официальный исходник сохранены
приватно. Это исследования одного хаба и типа логики. Физическую плавность
глазами владельца не проверяли. Нативная версия экземпляра или CAS не найдены:
совпадение адреса и параметров не доказывает прежнее владение после уже
наблюдённого исчезновения. Ненаблюдённое пересоздание между чтениями отличить
от прежнего назначения по этим данным нельзя.
