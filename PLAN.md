# Ближайший срез: нативная модель выбранного дома

Целевой опыт — в [VISION.md](VISION.md), работающий продукт — в
[README.md](README.md). Брифы, статусы и приёмка задач ведутся в
[Plan, проект SPRUT](https://plan.nuanu.ai/project/SPRUT).

## Продуктовый результат

В новом диалоге агент видит доступные учётной записи дома, явно выбирает один
из них и постепенно раскрывает нужную комнату, устройство, характеристику,
сценарий или физическую настройку. Одинаковые локальные ID разных домов не
смешиваются. Агент отличает текущее значение, редактируемую конфигурацию,
сообщённое устройством значение и неизвестный статус применения.

## Минимальный объём

Read-only инструменты `list_homes`, `inspect_home` и `get_entity` поверх
наблюдённых нативных операций SprutHub. Первый срез покрывает комнаты,
accessory → service → characteristic, сценарии с их реальным типом и
конфигурацией, расширения, назначенные логики и физические настройки через
`accessory.deviceWindow` → `window.get`.

Полный каталог хаба, pairing, события, dashboards, backups и новые операции
записи в этот срез не входят. Существующие записи автоматизаций остаются
привязаны к настроенному дому и явно отклоняют ссылки другого дома.

## Критерии готовности

- Офлайн-проверка с двумя домами и совпадающими локальными ID доказывает
  принадлежность каждой ссылки и каждого RPC выбранному serial.
- Подробность контрольного датчика раздельно возвращает characteristic option,
  настроенное физическое значение и независимую безопасную диагностику,
  неизвестный `reported`/`pending` и честную свежесть без связывания по option key
  или совпавшему имени свойства.
- BLOCK-сценарий возвращает JSON-конфигурацию, GLOBAL/LOGIC — нативный код как
  недоверенные данные; секреты не попадают в результат, логи и Git.
- Layout и команды окна не выдаются за настройки. Большая диагностика
  раскрывается только явно; единая выходная защита целиком скрывает распознанную
  credential-сущность терминальным валидным marker и сохраняет обычных соседей,
  включая при секрете в имени JSON-поля. Расширение адресуется только по
  уникальному native `extensionKey`. Ошибки содержат capability status и
  следующее действие.
- Существующие инструменты комнаты и автоматизации используют ссылки с домом;
  старые записи локального журнала продолжают работать через сохранённый
  fingerprint настроенного хаба.
- После независимого ревью Architect выполняет разрешённую живую проверку первого
  дома. Офлайн-успех не выдаётся за живую совместимость всех сущностей.
