# Рабочая стратегия

Текущее состояние, следующие шаги и действующие решения. Целевой продукт — в
[VISION.md](VISION.md), что уже работает — в [README.md](README.md), история
изменений и проверок — в Git. Разборы возвратов волн 3–4 —
[research/archive/2026-10-plan-decisions.md](research/archive/2026-10-plan-decisions.md).

## Как ведётся работа

- Волна — несколько связанных результатов. Каждый проходит разработку,
  независимое ревью свежим агентом, eval на настоящей модели, где меняется
  поведение агента, и живую проверку на хабе, где меняется запись. Исполнители и
  ревьюеры — субагенты Claude на Opus; правила — в [AGENTS.md](AGENTS.md).
- Усилие по ценности для дома. Редкий сбой (потерянный ответ, переподключение)
  получает честное «неизвестно, проверь»; после одной правки и одного ревью
  оставшийся редкий случай записывается как ограничение, а не чинится новым
  кругом.
- Поверхность для агента — бюджет: число инструментов, длина инструкций и
  описаний, результат Sonnet в eval. Новая возможность по умолчанию не
  добавляет инструментов.
- Живые проверки: читать можно всё; создавать только свои временные объекты и
  сразу удалять; свои сценарии можно запускать, если они действуют только на
  временные виртуальные устройства; настоящие устройства, сценарии и настройки
  дома — только с подтверждения владельца. Выпуск на GitHub — по согласованию.

## Следующие шаги

1. Новая сцена с кнопкой целиком («сделай сцену Рассвет и кнопку для неё»):
   палитра в GLOBAL, виртуальная кнопка и BLOCK «кнопка → код» уже есть по
   отдельности; нужен один eval-кейс на весь путь.
2. Упоминания устройств в коде: id в массивах и переменных (список ламп
   «Color scenes») сейчас не видны ни в связях устройства, ни в зависимостях
   удаления. Нужно перед «убери из сцен лампы, которых больше нет» и перед
   удалением физических устройств.
3. Кнопки окон устройств — сузить до «удали устройство из сети» с одним
   вопросом, после шага 2; калибровка клапана — проверка с владельцем.
4. Выпуск 0.6.0 — после проверок с владельцем, по его согласию.

Голос владелец делает в отдельной сессии; исследование платформ —
[research/voice/2026-10-13-realtime-tools.md](research/voice/2026-10-13-realtime-tools.md).

Проверки с владельцем в конце волны, одним заходом: настоящее
ZigBee-устройство (подключение, имя и комната, конец поиска по таймеру);
подключение Xiaomi (`joinRoom`, `joinButton`); перевязка группы после
настоящей замены лампы; экспорт устройства в работающую Алису и что видно в
её приложении; правка «Color scenes» на настоящих лампах и проверка сцены;
выход устройства из сети (событие `C_Online`); уведомления из сценариев —
после починки Telegram.

Позже: обслуживание (проверка связи, лечение, прошивка — с подтверждением),
резервная копия хаба, история показаний после установки History.

Известные мелочи: шаблон Wi-Fi QR квадратичен на длинном тексте; поле
`Ticket` окна Xiaomi покажет одноразовый код; поиск устройств при сбое записи
состояния говорит «сеть не открыта»; ошибка чтения журнала в
`prepare_native_change` и отмене даёт `internal_error`; LOGIC с секретом в
коде агент переименовать не может; `get_entity` показывает и скрытые
тестовые кнопки окон. Снимок дома: до первого события соединения каждый
ответ читает дом целиком, полное чтение дочитывает связи виртуальных ламп
(~250 мс на 9 групп), и событие, которое снимок не может применить, пришедшее
за это время при повторном полном чтении, отбрасывает чтение целиком;
`get_entity` показывает группы лампы только по свежему снимку; связи,
изменённые в приложении, видны не позже чем через 5 минут; старое полное
чтение, закончившееся позже нового, может на миг показать прежнее значение
записи. Отмена: после потерянного ответа и неудачного чтения отмены команды
устройству предлагается повтор без нового чтения; подтверждённая хабом более
новая команда без нового значения в чтении считается не применённой; отмена
удаления сценария создаст вторую копию, если владелец уже создал его сам.
Код: `hub_code_error` ловит только компиляцию и верхний уровень при записи,
ошибка внутри функции видна лишь в журнале при запуске сценария; методы
отклоняются по имени и у собственных объектов кода; поиск зависимостей кода
смотрит первые 24 сценария с кодом. Вход: каждый процесс MCP входит сам;
после отклонённого входа нужен перезапуск; `TOO_FAST` без задержки не
выжидается. Мосты: что видит приложение ассистента, с хаба не наблюдается.

## Действующие решения

- Цель — замена интерфейса, а не покрытие методов хаба: операция добавляется,
  когда без неё владельцу приходится открывать интерфейс.
- Неизвестный внешний контракт проверяется на хабе, а не угадывается.
- Правила поведения агента — в инструкциях сервера (не длиннее 2048 символов,
  главное в первых 512), правила инструмента — в его описании (до 1000).
- Истёкший запрос выводит из обращения только своё соединение; соседние
  запросы не теряют ответ.
- Поиск устройств хранится в каталоге состояния и переживает перезапуск
  сервера; новое — только ребёнок контроллера не из своих «до».
- Подпись со словом-секретом скрывает любое значение, кроме «да/нет».
- Отмена команд не возвращает яркость ламп со связью «включение и уровень»:
  запись уровня выключенной лампе её включает.
- У LOGIC имя, описание и запуск при старте меняются только через `info` в
  коде: хаб берёт их оттуда при каждой записи кода.
- Голос — отдельный слой поверх общего ядра; в сервере нет ничего
  специфичного для одной платформы.
- Голосовой стенд остаётся в Москве: OpenAI отклоняет запросы из региона,
  поэтому выход к нему идёт через VLESS к польскому серверу, а российские
  адреса и SprutCloud — напрямую.
- Свежесть снимка дома — один счётчик поколений: чтение, во время которого
  пришло неприменимое изменение, не используется.
- Неудачное чтение не ведёт ни к записи, ни к окончательному выводу: исход
  остаётся неизвестным с предложением повторить.
- Мостами (Алиса, HomeKit и другие) агент управляет по просьбе владельца
  (14.10.2026): включает и выключает в них конкретные устройства — после
  проверки записи экспорта на хабе.
- Перевязка групп ламп (23.10.2026, два возврата, бюджет исчерпан). Продукт
  давал состав группы, но не давал опознать замену; попытка вывести
  «кандидатов» и «новой лампы на хабе нет» дала ложные утверждения (лампа в
  другой комнате, белая вместо цветной). Решение владельца: чтения дают
  факты — состав группы, группы лампы с комнатой, свободные лампы комнаты и
  чего им не хватает — без выводов; `get_entity` не читает ради пометок весь
  дом. То, что Sonnet иногда открывает подключение нового устройства, —
  ограничение, без нового круга.
- Результат подготовки называет следующий вызов `apply_native_change`, когда
  запрос просит само изменение; когда владельцу сначала нужно что-то сказать,
  результат несёт `tell_owner` и следующего вызова не даёт (23.10.2026: без
  этого Sonnet готовил верное изменение и переспрашивал).
- Виртуальные устройства, второй возврат (23.10.2026). Исправление ревью
  включило непрочитанный код (`code_unread`) в зависимости, и одна проверка
  стала решать два разных вопроса: «сказать владельцу перед удалением» и
  «запретить отмену своего создания». В доме больше 24 сценариев с кодом
  отмена своего свежего устройства всегда отвечала «используется». Решение:
  отмену своего создания останавливают только найденные ссылки; непрочитанное
  называется в результате, но не запрещает. Сохраняется: найденную ссылку
  отмена не ломает, удаление по просьбе при любой зависимости или неизвестности
  сначала говорит владельцу. Один цикл «исправление → ревью».
- Удаление по просьбе (сценарий, виртуальное устройство): без найденных
  зависимостей — без вопроса; при найденной зависимости или неизвестности —
  сначала владельцу (`tell_owner`); отмена создаёт объект заново под новым
  номером или id и называет, что не вернулось. Физические устройства агент
  пока не удаляет (23.10.2026).
- Кнопки окон устройств отложены (23.10.2026, PM и чтение 96 окон дома): у
  владельца нет лечения, проверки связи и прошивки, смысл «Переспарить» не
  установлен, «Удалить все аксессуары» хаб выполняет без подтверждения, а
  упоминания устройств в коде GLOBAL пока не видны — удаление устройства
  молча сломало бы сцены. Первой будет «удали устройство из сети» с одним
  вопросом, после видимости id в коде.
- Тесты изолированы от настоящего дома: временный `HOME`, без переменных
  подключения, соединения только на локальные адреса (23.10.2026: новый тест
  без явного подключения прочитал бы учётные данные владельца).
- Плагин публикуется только по согласованию с владельцем. С 12.10.2026 проект
  отвязан от Plan; стратегия ведётся в репозитории.
