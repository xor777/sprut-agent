# Ближайший срез: прямое подключение к SprutHub

Целевой опыт — в [VISION.md](VISION.md), работающие инструменты — в
[README.md](README.md). Постановка и приёмка подключения — в
[SPRUT-17](https://plan.nuanu.ai/project/SPRUT/issue/17).

## Продуктовый результат

Владелец хранит локально только логин и пароль SprutHub. MCP самостоятельно
проходит нативный вход, проверяет доступные дома, сохраняет закрытую локальную
сессию и повторно использует её после перезапуска. Секреты и приватные данные
шагов авторизации не попадают в ответы агента, логи или Git.

## Минимальный объём

Нативные `account.auth` и `account.answer` поверх существующего WebSocket
JSON-RPC, challenge Argon2id/Ed25519 и локальный session-файл с ограниченными
правами. Beta endpoint задан по умолчанию, явный URL и прежний путь с готовыми
token/cid/serial сохраняются. OAuth, WebView, Keychain, UI и новые сервисы в
срез не входят.

## Критерии готовности

- Один набор login/password запускает публичное MCP-чтение без ручного извлечения
  token, cid или serial; конкурентные первые вызовы разделяют один вход.
- Проверенная сессия атомарно сохраняется вне Git с режимом `0600` и повторно
  используется следующим процессом. Логин, пароль и challenge-ответ не
  сохраняются в session-файле и не возвращаются агенту.
- Поддерживаемые EMAIL, PASSWORD и CHALLENGE имеют ограниченный порядок и
  ресурсы. Неизвестный шаг, enrollment, задержка, несовместимый ответ или потеря
  соединения после отправки останавливают flow без слепого повтора ответа.
- При одном доме операции без home-qualified ref получают безопасный default.
  При нескольких домах явное чтение работает по ссылке, но запись требует
  заранее выбранный `SPRUTHUB_SERIAL` и не наследует выбор из чтения.
- Старый журнал автоматизаций и явная конфигурация URL/token/cid/serial работают
  без миграции.
- Синтетическая публичная проверка фиксирует wire-envelope, криптографический
  вектор, повторный процесс, ошибки и многодомную границу на Node 24. Реальный
  login/read/restart подтверждает Architect после локального заполнения файла.
