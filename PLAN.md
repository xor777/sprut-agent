# Ближайший срез: нативный сценарий с проверяемым откатом

Целевой опыт — в [VISION.md](VISION.md), работающий продукт — в
[README.md](README.md). Брифы, статусы и приёмка задач ведутся в
[Plan, проект SPRUT](https://plan.nuanu.ai/project/SPRUT).

## Продуктовый результат

Пользователь поручил включать офисную лампу по движению на выбранном датчике,
переносить выключение при каждом новом событии и выключать лампу после минуты
без новых событий.
Агент изучает существующие связи и логики, выбирает нативный механизм, показывает
конкретную автоматизацию, создаёт её в пределах поручения и проверяет результат. По просьбе пользователя восстанавливает
предыдущее состояние. Сценарий остаётся доступен в интерфейсе SprutHub
и исполняется на хабе без агента.

## Предпосылки

Поручение задаёт движение → включение лампы → выключение через 60 секунд от
последнего события движения. Изменения других устройств в него не входят.
Конкретные ссылки и критерии — в задаче Plan. Создаётся один новый BLOCK с одним
нативным `RESET` delay; существующая логика лампы сохраняется.

Сначала подтвердить на целевом хабе структуру сценария и привязок, способ
прочитать исходное состояние и границы его восстановления. Источники —
[нативная модель и документация](research/protocol/2026-09-09-model.md).
Наблюдённые нативные механизмы — в
[исследовании автоматизаций](research/protocol/2026-09-09-automations.md).
Для нового сценария откат означает удалить только созданный нами объект,
сохранив последующие ручные правки и остальные автоматизации.

## Минимальный объём

Один тип сценария, одно изменение и сохранённая история изменения вместе
с причиной и результатом проверки. Используем существующий пакет и нативные
операции SprutHub. Сначала проходит весь путь агент → инструмент → хаб →
проверка → восстановление; хранение расширяется только по потребности этого пути.

## Критерии готовности

- Новый агентный диалог находит выбранный сценарий и его реальные зависимости,
  читает существующие механизмы и объясняет выбор без подмены ID именами.
- Предварительный просмотр не меняет дом. Применение затрагивает только
  согласованный сценарий; подтверждение команды отделено от прочитанного
  состояния и наблюдённого физического эффекта.
- Параллельная ручная правка обнаруживается до перезаписи. При неопределённом
  результате или разрыве связи агент сначала устанавливает текущее состояние.
- Восстановление возвращает исходную конфигурацию и привязки выбранного
  сценария; результат сверяется с хабом. Уже произошедший физический эффект
  не объявляется отменённым.
- Продуктовые RED/GREEN-проверки через MCP предшествуют реализации; подмена
  внешнего хаба основана на наблюдённом обмене. Конкретные сомнения проверяются
  адресными мутациями по правилам AGENTS.
- После независимого ревью пройден разрешённый живой сценарий и проверен
  откат. Офлайн-успех сам по себе не закрывает срез.
