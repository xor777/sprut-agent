# sprut-agent

**Agent-first интеграция для умного дома на SprutHub.**

[![CI: GitHub Actions](https://img.shields.io/badge/CI-GitHub_Actions-24292F?logo=githubactions&logoColor=white)](https://github.com/xor777/sprut-agent/actions/workflows/check.yml)
[![Node.js 24.11+](https://img.shields.io/badge/Node.js-24.11%2B-417E38?logo=nodedotjs&logoColor=white)](package.json)
[![MIT License](https://img.shields.io/badge/License-MIT-2563EB)](LICENSE)

sprut-agent даёт ИИ-агенту программный доступ к SprutHub: читать дом, настраивать
ограниченный набор нативных автоматизаций и разбираться в их поведении. Сценарии
исполняются на хабе и остаются видимыми в его интерфейсе. Целевой опыт описан в
[видении продукта](https://plan.nuanu.ai/project/SPRUT/docs/176).

> [!IMPORTANT]
> Проект на ранней стадии. Чтение, вход по логину и паролю, сохранение сессии,
> BLOCK/property, ограниченный световой путь назначаемой logic и собственный
> LOGIC проверены через публичный MCP на настоящем SprutHub. Не все классы
> устройств, автоматизаций и отказов прошли живую приёмку. Pairing, backup,
> GLOBAL и произвольная запись вне опубликованного контракта не поддерживаются.

## Установка

Поставка содержит один MCP-runtime и один предметный skill `spruthub-master`.
Проверенные клиентские рецепты ниже подключают именно этот общий комплект;
Codex для запуска через Claude Code не нужен.

### Claude Code

Рецепт проверен с Claude Code 2.1.267 на Linux. Нужны Node.js 24.11+, Git,
доступ к GitHub и своему SprutHub. Агенту достаточно дать ссылку
`https://github.com/xor777/sprut-agent` и сказать: «Помоги установить sprut-agent
в Claude Code и подключить мой дом. Не проси меня передавать пароль в чат».

Штатная установка одновременно подключает MCP и skill:

```sh
claude --version
node --version
git --version
claude plugin marketplace add xor777/sprut-agent
claude plugin install sprut-agent@sprut-agent
claude plugin list --json
```

После установки начни новый диалог. Команда `/mcp` должна показывать подключённый
сервер из plugin, а `/sprut-agent:spruthub-master` — поставляемый skill. Plugin
использует абсолютный путь своей установленной копии, поэтому диалог можно
запускать из любой папки. Повторная установка сохраняет соседние настройки
Claude Code и локальные данные sprut-agent.

### Codex

Проверенный путь рассчитан на Codex CLI 0.154.0 или новее на macOS arm64.
Нужны Node.js 24.11+, npm, Git, доступ к GitHub и своему SprutHub. Перед
изменением профиля агент проверяет реальные предпосылки:

```sh
codex --version
node --version
npm --version
git --version
```

Новому агенту достаточно дать ссылку
`https://github.com/xor777/sprut-agent` и сказать: «Помоги установить sprut-agent
и подключить мой дом. Не проси меня передавать пароль в чат». Агент устанавливает
единый комплект MCP и skill штатными командами Codex:

```sh
codex plugin marketplace add https://github.com/xor777/sprut-agent.git --ref main
install_result="$(codex plugin add sprut-agent@sprut-agent --json)"
installed_path="$(node -p 'JSON.parse(process.argv[1]).installedPath' "$install_result")"
node "$installed_path/check-install.mjs" "$installed_path"
```

Последняя команда проверяет transport, runtime и skill из выбранной установленной
копии. Если имя MCP `sprut-agent` уже занято другой настройкой, проверка
сохраняет её и объясняет продолжение. Удалять такую запись через
`codex mcp remove sprut-agent` можно только после подтверждения владельца, что
она больше не нужна. Отключённый в Codex skill включается штатной настройкой
навыков; повторная установка плагина сама его не включает.

### Подключение дома

В любом из проверенных клиентов сначала спроси: «Подключи мой SprutHub. Не проси
меня передавать пароль в чат». При отсутствии реквизитов MCP возвращает точный
путь локального файла и следующий безопасный шаг. Агент готовит файл, а логин и
пароль владелец вводит в него сам, не в чат:

```sh
mkdir -p "$HOME/.config/sprut-agent"
chmod 700 "$HOME/.config/sprut-agent"
touch "$HOME/.config/sprut-agent/connection.env"
chmod 600 "$HOME/.config/sprut-agent/connection.env"
```

Содержимое `connection.env`:

```dotenv
SPRUTHUB_LOGIN=ваш_логин
SPRUTHUB_PASSWORD=ваш_пароль
```

После сохранения файла начни новый диалог, тем самым перезапустив MCP, и спроси:
«Какая сейчас температура в офисе?». При одном доступном доме агент выберет его
явно, при нескольких попросит уточнить дом. Успешный вход сохраняет сессию рядом
с настройкой, поэтому следующий процесс не требует пароль повторно.
Credential-файл, сессия и журнал изменений находятся вне кэша plugin и
переживают повторную установку.

Шаги установки безопасно повторять. `authentication_failed` означает отказ в
реквизитах, `connection_failed` — недоступность хаба. Исправь
`connection.env` и перезапусти MCP; переустановка не нужна. Plugin запускает
готовый bundle из собственного кэша и не выполняет `npm install` или сетевую
загрузку при старте.

<details>
<summary>Переход с прежнего ручного MCP и дополнительные профили</summary>

У прежнего пользователя может остаться пара ручного MCP `sprut` и
пользовательского skill `spruthub-master`. `check-install.mjs` находит
активные skills через Codex и не сообщает готовность, пока прежний skill может
направить новый диалог к старому MCP. Для распознанной прежней установки проверка
печатает точную команду, которая отключает только этот skill, не удаляя его
симлинк, target, старый MCP или соседние настройки. Произвольный одноимённый
skill молча не отключается.

`SPRUTHUB_URL` и `SPRUTHUB_SERIAL` применяются и вместе с логином/паролем.
Для готовой сессии вместо логина/пароля укажи `SPRUTHUB_TOKEN`,
`SPRUTHUB_CID` и обязательный `SPRUTHUB_URL`. При нескольких доступных домах
явный `SPRUTHUB_SERIAL` в том же `connection.env` выбирает дом для сценариев,
истории и SDK, включая их чтение, а также для `list_rooms`. Для адресного обзора
дома `inspect_home` и `read_services` принимают `home_ref`. При
`home_selection_required` выполни возвращённый вызов `list_homes`: его
`selection.options` содержит точное значение для выбранного дома, а
`selection.pin` — фактический источник настройки, поле и шаг перезапуска. Для
обычной plugin-установки это локальный `connection.env`; если реквизиты переданы
окружением запуска MCP, выбор нужно добавить в то же окружение. После этого
повтори исходную операцию. Адресные чтения можно начать сразу с выбранным
`home_ref`, не закрепляя дом. Пустой каталог возвращает конечную причину
`no_available_homes` и не предлагает закреплять отсутствующий дом.
`SPRUTHUB_TIMEOUT_MS` задаёт deadline; по умолчанию вход и обычный запрос ждут
не более 10 секунд. Эти значения хранятся в том же локальном credential-файле.

</details>

Установка Claude Code plugin проверена штатным клиентом из другой рабочей папки:
клиент загрузил общий skill и 19 MCP-инструментов. Установка по Git-ссылке и
переход с прежнего ручного комплекта проверены свежим агентом на macOS arm64 с
Codex CLI 0.154.0 и синтетическими хабами. Из общего установленного bundle
отдельно проверены вход, чтение настоящего SprutHub и повторный запуск с
сохранённой сессией. Секреты агенту не передавались.

## Как работает агент

Агент выбирает дом через `list_homes`, получает компактный контекст через
`inspect_home` и находит именованные services по дому через каталожное
представление `read_services`, без значений каждого совпадения. Только для выбранной
сущности он раскрывает значения и подробности через `get_entity`. Ответы сохраняют
устойчивые home-qualified refs, единицы, enum, доступность, свежесть и признаки
полноты; текст устройств и сценариев считается недоверенными данными.

Изменения проходят через `get_native_change_contract` →
`prepare_native_change` → `apply_native_change`. Состояние и возврат доступны
через `get_native_change`, `list_native_changes` и
`restore_native_change`. Preview boolean → boolean BLOCK остаётся отдельным
совместимым входом. Подготовка не меняет хаб, timeout записи оставляет исход
неизвестным до сверки, а последующая ручная правка блокирует автоматическое
восстановление этим change даже при позднейшем совпадении с запрошенным
значением; следующий разрешённый шаг готовится новым change.

Актуальные операции, точные поля, ограничения readback и восстановления
описаны в [проверенном контракте
SprutHub](skills/spruthub-master/references/spruthub-contract.md). Порядок выбора
бытового решения находится в [skill](skills/spruthub-master/SKILL.md), а
расследование сбоев — в [diagnostics-workflow](skills/spruthub-master/references/diagnostics-workflow.md).
README намеренно не дублирует публичный API.

### Наблюдение событий

`start_native_observation` сразу возвращает `observation_ref`; результат
читается через `get_native_observation`, досрочное завершение — через
`stop_native_observation`. Наблюдение ограничено выбранным домом,
характеристиками и одним сценарием, не меняет его конфигурацию и не доказывает
физическую причинность по близким временам событий. Точные лимиты и статусы
зафиксированы в [контракте](skills/spruthub-master/references/spruthub-contract.md).

### Программное чтение

Для собственного Node-приложения импортируй `createSprutHubReader` из
`<plugin-root>/dist/read.mjs`:

```js
import { createSprutHubReader } from "<plugin-root>/dist/read.mjs";

const reader = createSprutHubReader();
const result = await reader.read({
  homeRef,
  readings: [{ ref: characteristicRef, label: "office_temperature" }],
});
await reader.close();
```

Reader использует общий локальный credential-профиль и экспортирует только
чтение. Логин, пароль, token и session не попадают в показания.

### Код, исполняемый на хабе

Перед созданием LOGIC `get_scenario_sdk` возвращает текущие декларации sandbox
выбранного хаба. `sdk_complete=true` означает полный `sdk`;
`sdk_complete=false` — частичное содержимое, заменённое защитным marker.
`bytes` и `sha256` всегда описывают фактически возвращённый `sdk`, а
freshness — время ответа. Это API кода на хабе, не Node/browser SDK; локально код
не исполняется.

## Из чего состоит проект

Один пакет на JavaScript, Node.js и npm. MCP-сервер запускается одним процессом:

```text
ИИ-агент → MCP по stdio → sprut-agent → JSON-RPC по WebSocket → SprutHub
```

| Компонент | Назначение |
| --- | --- |
| [MCP-сервер](src/server.mjs) | Публичные инструменты чтения, изменения и наблюдения |
| [Подключение](src/spruthub-connection.mjs) | Нативный вход, проверка и локальное сохранение сессии |
| [Клиент SprutHub](src/spruthub-client.mjs) | Узкий набор нативных WebSocket-запросов и преобразование ошибок |
| [Read-only API](src/read-api.mjs) | Публичное программное чтение выбранных характеристик |
| [Skill](skills/spruthub-master/) | Порядок выбора, предметные карточки, контракт и диагностика |
| [Исследования](research/) | Утилиты, датированные наблюдения и снимки протокола |

Основной путь не зависит от расположения кнопок интерфейса. Изменение протокола
хаба всё ещё может потребовать обновления клиента.

## Исследование протокола

| Команда | Результат |
| --- | --- |
| `npm run research:diff -- --from <снимок> --to <снимок>` | Сравнение схем и каталога операций |
| `npm run research:record -- --cdp-url http://127.0.0.1:9222` | Пассивная запись WebSocket-событий через Chrome DevTools Protocol |
| `npm run research:snapshot` | Попытка извлечь схемы и метаданные из публичной сборки |

Recorder требует отдельную браузерную сессию с CDP и ручную авторизацию. Raw
captures сохраняются с правами `0600` в исключённом из Git каталоге и могут
содержать секреты; санитайзер пока не реализован.

Снимок `1.5.58` относится к сборке 2025-09-16. Полный snapshot CLI не принят на
текущей публичной сборке: ранее он остановился на распознавании build. Отдельная
функция извлечения protobuf-модулей текущий JS прочитала; нативные каталоги типов
проверены на хабе. Источники, версии и границы находятся в
[research/protocol/](research/protocol/).

## Разработка

Нужны Node.js 24.11+, npm и Git. Полная команда также проверяет Codex-адаптер,
поэтому для `npm run check` нужен Codex CLI 0.154.0 или новее:

```sh
git clone https://github.com/xor777/sprut-agent.git
cd sprut-agent
npm ci
npm run check
```

Корневой `.mcp.json` запускает bundle из checkout, когда процесс стартует из
корня репозитория. Эквивалентная команда:

```sh
cd /absolute/path/to/sprut-agent
node ./dist/plugin/dist/server.mjs
```

Из другой папки передай клиенту абсолютный путь
`/absolute/path/to/sprut-agent/dist/plugin/dist/server.mjs`. Установленный
Codex plugin использует `./dist/server.mjs` внутри своего каталога и не зависит
от checkout или текущей папки клиента.

```sh
npm run check           # Bundle, Biome и офлайн-тесты
npm run test:mutations  # Необязательная адресная диагностика
```

`npm run check` воспроизводимо собирает поставляемый комплект, проверяет
отсутствие diff, запускает тесты публичных MCP/SDK-входов и устанавливает plugin
реальным Codex CLI в изолированный профиль. Внешняя граница тестов — локальный
native-shaped WebSocket-хаб; это не живая проверка SprutHub.

Переносимый agent-smoke:

```sh
npm run eval:spruthub-master
npm run eval:spruthub-master -- contact-option plugin
```

Он использует новый временный профиль, синтетический хаб и сохраняет
доказательства вне репозитория. Успешный exit подтверждает завершение запуска,
но не заменяет независимый продуктовый вердикт. Ручной сценарий неоднозначной
комнаты доступен через `node research/check-agent-room-ambiguity.mjs ambiguous`.

Git использует Conventional Commits. Правила тестирования, RED/GREEN, ревью,
веток и рабочей копии — в [AGENTS.md](AGENTS.md); [CLAUDE.md](CLAUDE.md)
ссылается на тот же файл.
