# sprut-agent

Локальный MCP-сервер для чтения устройств и показаний одной комнаты SprutHub,
а также исследовательские инструменты протокола. Продуктовый путь проверен
офлайн через настоящий MCP stdio-процесс и небольшой WebSocket-сервер хаба;
совместимость с выбранным настоящим хабом пока не подтверждена.

- [VISION.md](VISION.md) — зачем создаём продукт и каким должен быть результат.
- [PLAN.md](PLAN.md) — ближайший сквозной результат и критерии готовности.
- [AGENTS.md](AGENTS.md) — правила разработки и порядок документирования.
- [package.json](package.json) — исполняемые команды проекта.

## Начать

Node.js 24 и npm:

```sh
npm ci
npm run check
npm run test:mutations
```

Git hooks проверяют Conventional Commits при коммите и `npm run check` перед push.
Промежуточные RED-коммиты разрешены; отправлять нужно зелёную голову ветки.
Обычный CI на `push` и `pull_request` выполняет `npm run check` и проверяет
сообщения коммитов. Полный Stryker запускается вручную действием
`workflow_dispatch` после быстрых проверок; доступ к дому ему не нужен.
Новый автоматический запуск ветки отменяет её устаревший запуск.

## Читать комнату через MCP

Сервер предоставляет один read-only инструмент `read_room`. Вход `room`
принимает обычное название комнаты или полученную ранее устойчивую ссылку
`spruthub://room/<id>`. Результат сохраняет ссылки комнаты, устройств, сервисов
и характеристик, доступность, значения и единицы. Возможные статусы:

- `ok` — комната найдена; пустой `devices` означает существующую пустую комнату;
- `ambiguous` — совпали несколько комнат, в `candidates` есть ссылки для уточнения;
- `error` — структурированная причина и возможность повтора.

Настрой подключение локально в окружении MCP-процесса; значения не должны
попадать в Git, логи или ответы инструмента:

```sh
SPRUTHUB_URL=wss://example.invalid/spruthub \
SPRUTHUB_TOKEN=local-secret \
SPRUTHUB_SERIAL=local-hub-serial \
SPRUTHUB_CID=local-client-id \
npm start
```

`SPRUTHUB_TIMEOUT_MS` необязателен; по умолчанию один запрос ждёт не более
10 секунд. MCP-клиент должен запускать `npm start` из корня репозитория и
передавать эти переменные собственным безопасным способом.

`freshness.hubResponseReceivedAt` — локальное время получения полного ответа
хаба. `measurementAt: null` означает, что подтверждённое время самого измерения
не получено; время ответа не выдаётся за время измерения. Каждый вызов читает
данные заново. После временной ошибки можно повторить тот же инструмент в том же
MCP-сеансе; успешный старый ответ не кэшируется.

Текущий JSON envelope основан на статическом контракте web-клиента `1.5.58`,
а не на наблюдении актуальной прошивки. До live-приёмки не подтверждены адрес,
обычная авторизация, фактические поля текущей версии, два состояния физического
датчика и восстановление реального соединения. Инструмент ничего не записывает
в дом.

## Задачи в Plan

Рабочие задачи и передачу результатов ведём в
[проекте SPRUT в Plan](https://plan.nuanu.ai/project/SPRUT). Проектный конфиг
[`.codex/config.toml`](.codex/config.toml) подключает его MCP только в этом
репозитории. Codex должен доверять каталогу проекта. Для авторизации выполни
из корня репозитория:

```sh
codex mcp login plan
```

OAuth-данные хранит Codex вне репозитория; API-ключ в конфиг не нужен.
Включены инструменты чтения проекта и работы с задачами и комментариями.
После добавления конфигурации перезагрузи MCP в клиенте или открой новую сессию
в этом каталоге. Проектная настройка определяет доступность инструмента в Codex;
права на данные в Plan определяются аккаунтом и настройками доступа самого Plan.

## Исследовательские инструменты

```sh
npm run research:diff -- --from research/snapshots/1.5.58 --to research/snapshots/1.5.58
npm run research:record -- --cdp-url http://127.0.0.1:9222
npm run research:snapshot
```

Recorder пассивно записывает CDP WebSocket events в `research/captures/raw/`.
Нужна отдельная браузерная сессия с CDP и ручная авторизация. После запуска записи
перезагрузи страницу; остановка — Ctrl-C. Raw captures могут содержать секреты:
они исключены из Git и создаются с правами `0600`. Санитайзер пока не реализован.

Снимок `1.5.58` относится к сборке 2025-09-16. Проверка 2026-09-09 показала, что
extractor не определяет build публичной сборки 2026-08-31; его эвристики имён
proto и каталога RPC также не соответствуют этой сборке. Номер версии интерфейса
недостаточен для выбора контракта. Локальные тесты не доказывают совместимость
с текущей прошивкой хаба.

`research/archive/` содержит прежние архитектурные черновики; `research/protocol/`
— исторический журнал. Это материалы исследования, не актуальный backlog.

## Что доказывают проверки

`npm test` запускает офлайн-тесты. Продуктовые тесты используют официальный
MCP-клиент, настоящий дочерний stdio-процесс приложения и внешний локальный
WebSocket-сервер. Они проверяют выбор комнаты, ссылки, значения, единицы,
повторное чтение, неоднозначность, неполные ответы, авторизацию, ограниченный
таймаут, обрыв и восстановление. Recorder отдельно проверяется с локальным
CDP-сервером. Это не live-проверка SprutHub.

Область Stryker явно указана в `stryker.config.json`: существенная логика нового
MCP/Hub-пути и прежний исправленный выбор сокета recorder. Результат не описывает
покрытие всего репозитория или совместимость с настоящим хабом.

Историю RED/GREEN и выполненные проверки смотри в коммитах. Схемы и снимки
генерируются инструментами; их нельзя править форматтером вручную.
